Observabilidad del backend, ahora corriendo en Azure AKS

El API .NET emite métricas, trazas y logs con OpenTelemetry. Desplegamos en el clúster AKS dev el stack que los recibe y los muestra en Grafana. Esta página explica, en lenguaje simple y con capturas reales del clúster, qué quedó funcionando.

Entorno: Azure AKS dev (suscripción Azure 02 · westus3)  •  Namespace: observability  •  Fecha: 18 jun 2026  •  Antes: esto vivía solo en local (Docker Compose); ahora es real en la nube.

1 ¿Qué es la observabilidad y cómo fluye?

La idea es simple: la aplicación no guarda ni dibuja nada por su cuenta. Solo emite su telemetría en un formato estándar (OTLP) hacia un Collector, y este la reparte a tres almacenes especializados que luego Grafana junta en una sola pantalla. Cambiar de "local" a "AKS" fue, esencialmente, cambiar a dónde apunta ese envío.

Los 3 pilares de la observabilidad: Métricas (¿cuántas requests, cuántos errores, qué tan lento?), Trazas (¿por dónde pasó cada request por dentro?) y Logs (¿qué dijo la app en cada paso?). Juntos responden no solo "algo falla" sino "qué, dónde y por qué".

3 Evidencia real del clúster (capturas)

Cada captura es del Grafana/Prometheus corriendo en AKS, con datos generados por tráfico real al API. Lee de izquierda a derecha: a la izquierda qué estás viendo, a la derecha la pantalla.

Métricas · Grafana

Dashboard RED

RED = Rate, Errors, Duration. Es la forma estándar de resumir la salud de un servicio web en tres preguntas:

  • Rate — cuántas requests por segundo, total y por ruta (/api/Home, /healthcheck…).
  • Errors — % de respuestas 5xx y el desglose por código (200 / 404 / 405).
  • Duration — latencia p50 / p95 / p99 (la experiencia del usuario típico y del peor caso).

Incluye además la memoria del proceso .NET. Todo con datos reales del API en AKS.

Trazas · Tempo

Seguimiento de cada request

Una traza es la "radiografía" de una request: su recorrido por dentro del API (entrada HTTP → controlador → consulta a la base de datos) con el tiempo que tomó cada tramo.

  • Cada fila es una traza del servicio api-solution-test-ventas.
  • Se ve el método (GET), la duración y el identificador único de traza.
  • Sirve para responder "¿por qué esta request fue lenta?" abriendo su detalle.
Logs · Loki

Logs centralizados y correlacionados

Loki guarda los logs que emite el API (vía Serilog → OTLP). En la captura, la consulta {service_name="api-solution-test-ventas"} trae los mensajes del servicio, con un histograma de volumen arriba.

  • Se ven líneas reales: Request finished HTTP/1.1 GET ….
  • Cada log lleva su trace_id, así que desde un log saltas a su traza (y viceversa).
  • Esa correlación logs↔trazas↔métricas es lo que hace potente a Grafana.
Alertas · Prometheus

Reglas de alerta cargadas

Prometheus evalúa reglas y avisa cuando algo se sale de lo normal. Se cargaron nuestras tres familias (en estado Inactive = todo sano):

  • App (RED): HighApiErrorRate (5xx > 5%) y HighApiLatencyP95 (p95 > 1s).
  • Infraestructura: CPU alta/crítica, memoria alta, disco bajo.
  • Disponibilidad: TargetDown (un componente deja de responder).

El ciclo de una alerta es Inactive → Pending → Firing, y al dispararse llega a AlertManager.

Detalle técnico que vale la pena saber: el API exporta sus métricas cada 60 s. Por eso los paneles de tasa necesitan una ventana de cálculo de rate(...[5m]) (no [1m]) para tener suficientes muestras; con [1m] salían vacíos. Ya quedó corregido en el dashboard.

4 Estado y siguiente paso

La observabilidad self-hosted está desplegada y verificada en AKS dev. La presentación del proyecto ya usa estas capturas de AKS (no las locales). Si se quiere dejar permanente, conviene incorporar el dashboard y las reglas al Helm/values del repo y promover el stack a qa/prod por el flujo habitual. Para producción real: exponer Grafana con TLS y mover la contraseña a un secreto.

5 Glosario rápido — por si te preguntan "¿qué es...?"

Cada término que aparece arriba, explicado en una línea.

ObservabilidadPoder entender qué pasa DENTRO de un sistema mirándolo desde afuera, a partir de las señales que emite.
Los 3 pilaresMétricas (números), Trazas (recorridos) y Logs (mensajes). Juntos dicen qué falla, dónde y por qué.
MétricasNúmeros agregados en el tiempo: requests por segundo, % de errores, latencia, memoria.
TrazasEl recorrido completo de UNA request por dentro del sistema (HTTP → controlador → base de datos), con el tiempo de cada tramo.
LogsLos mensajes de texto que la app escribe en cada paso (ej. "Request finished ... 200").
trace_idUn identificador que conecta el log, la traza y las métricas de una MISMA request, para saltar de uno a otro.
OpenTelemetry (OTel)Estándar abierto para que las apps emitan métricas, trazas y logs de forma uniforme, sin atarse a un proveedor.
OTLPEl protocolo de OpenTelemetry: el "formato de envío" con que la app manda su telemetría.
InstrumentaciónEl código que se agrega a la app para que emita esas señales (en .NET: AddObservability() + Serilog).
OTel CollectorEl "hub" central: recibe la telemetría de la app y la reparte a cada almacén (Prometheus/Tempo/Loki).
PrometheusBase de datos de métricas + motor que evalúa las reglas de alerta.
TempoEl almacén de trazas (de Grafana).
LokiEl almacén de logs (de Grafana), pensado para buscar texto a gran escala.
GrafanaLa herramienta de visualización: dashboards y la pantalla "Explore" donde se ve y correlaciona todo.
AlertManagerRecibe las alertas que dispara Prometheus y las enruta/agrupa (ej. manda email, evita duplicados).
Método REDForma estándar de medir un servicio web: Rate (tasa), Errors (errores) y Duration (latencia).
remote-writeLa forma en que el Collector "empuja" las métricas hacia Prometheus.
PromQLEl lenguaje de consulta de Prometheus (con el que se arman los paneles y alertas).
rate(...[5m])Función de PromQL: calcula la tasa por segundo en una ventana de 5 min. Con ventana muy corta y datos cada 60s, no alcanzan las muestras.
p95 (percentil 95)El 95% de las requests fue más rápido que ese valor; mide el "peor caso típico" de latencia.
PrometheusRule / regla de alertaUna condición que, si se cumple durante cierto tiempo, dispara una alerta (ej. 5xx > 5% por 2 min).
Node ExporterAgente que expone métricas del servidor/host: CPU, memoria, disco.
kube-prometheus-stackUn paquete de Helm que instala Prometheus + Grafana + Alertmanager (y más) de una sola vez.
HelmEl "gestor de paquetes" de Kubernetes: instala aplicaciones completas en el clúster con un comando.
AKSAzure Kubernetes Service: el Kubernetes gestionado de Azure donde corre todo esto.
NamespaceUna "carpeta" lógica dentro de Kubernetes para agrupar recursos (aquí: observability).
port-forwardUn túnel temporal para abrir un servicio interno del clúster (ej. Grafana) desde tu propia PC.
